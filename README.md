# ربات دانلودر اینستاگرام به تلگرام

هر ۱۵ دقیقه پیج‌های ثبت‌شده در `config.yaml` را بررسی می‌کند و پست یا استوری تازه را مستقیم به بات تلگرام تو آپلود می‌کند. اجرا روی زمان‌بند رایگان گیت‌هاب اکشنز، بدون سرور.

## فایل‌ها

- `bot.py` — هسته‌ی کار: گرفتن پست و استوری تازه، دانلود، آپلود به تلگرام.
- `config.yaml` — پیج‌هایی که دنبال می‌کنی.
- `make_session.py` — یک بار روی کامپیوتر خودت اجرا می‌شود تا کوکی نشست بسازد.
- `state.json` — شناسه‌ی چیزهای دیده‌شده. ربات خودش این فایل را می‌سازد و در هر اجرا به ریپو کامیت می‌کند تا تکراری ارسال نشود.

## راه‌اندازی

۱. در BotFather یک بات بساز و توکنش را بردار. بعد پیامی به بات بده تا `chat_id` خودت را پیدا کنی (مثلاً از `@userinfobot`).

۲. یک ریپوی **خصوصی** بساز و این فایل‌ها را داخلش بگذار.

۳. با پایتون ۳.۱۲ یا جدیدتر، یک بار نشست بساز:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # روی ویندوز
# .venv/bin/python -m pip install -r requirements.txt     # روی لینوکس و مک
.venv/Scripts/python make_session.py نام_کاربری_اکانت_دوم
```

اسکرین‌نام و رمز را می‌پرسد. اگر تایید دومرحله‌ای دارد، کد را هم می‌خواهد. در آخر یک رشته‌ی طولانی base64 چاپ می‌کند.

۴. در تنظیمات ریپو، بخش Settings → Secrets and variables → Actions، این چهار مقدار را بساز:

| نام | مقدار |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن بات |
| `TELEGRAM_CHAT_ID` | شناسه‌ی چت تو |
| `IG_USER` | اسکرین‌نام اکانت دوم |
| `IG_SESSION_B64` | آن رشته‌ی base64 از مرحله‌ی ۳ |

۵. در `config.yaml` پیج‌های هدف را بنویس و push کن.

۶. از تب Actions دکمه‌ی Run workflow را بزن تا یک بار دستی اجرا شود و نتیجه‌ی تلگرام را ببینی. بعد از آن خودکار هر ۱۵ دقیقه کار می‌کند.

## نکته‌های مهم

- اکانت دوم باید پیج‌های خصوصی را فالو داشته باشد، وگرنه چیزی از آن‌ها نمی‌آید.
- اگر نشست بعد از مدتی از کار افتاد، ربات در لاگ خطای لاگین می‌دهد؛ فقط مرحله‌ی ۳ را تکرار کن و `IG_SESSION_B64` را عوض کن.
- در اولین اجرا فقط ۱۰ آیتم تازه از هر پیج می‌رود تا تلگرام پر از اسپم نشود. برای تغییرش `MAX_NEW_PER_RUN` را به‌عنوان variable در Actions تنظیم کن.
- ریسک اصلی محدودشدن خودِ اکانت دوم است. تعداد فالوهای کم و فاصله‌ی ۱۵ دقیقه‌ای معمولاً امن می‌ماند، اما تضمینی وجود ندارد.
- دسترسی write روی ریپو لازم است، چون `state.json` دوباره کامیت می‌شود.
